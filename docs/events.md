# 認証の記録に残す出来事（イベント）

Tenkyu における認証やセッション管理で発生する出来事（イベント）の定義と、記録に関する決まりです。

## 概要

認証の記録（`auth_events` など）には、「いつ、どの手段で、どのサービスに、成功・失敗したか」を残します。
何を残し、何を残さないかを明確にし、安全な監査と運用の両立を図ります（ADR 0004、ADR 0017、docs/schema.md）。

---

## 出来事の種類（イベント一覧）

認証の記録に残す出来事の一覧です。名前、意味、および記録に残す項目を定めます。

| 出来事 | イベント名 | 意味 | 残す項目 |
| --- | --- | --- | --- |
| コードの発行 | `code_issue` | 認証用の確認コード（メールの6桁コード等）を生成・保存した | 発生時刻、対象サービス、認証手段（`email_code` 等）、結果（成功/失敗） |
| コードの送信 | `code_send` | 生成された確認コードをメール等の配送サービス経由で送信した | 発生時刻、対象サービス、認証手段、結果（配送APIの成功/失敗） |
| コードの検証 | `code_verify` | 利用者が入力した確認コードを照合・検証した | 発生時刻、対象サービス、認証手段、結果（照合成功/不一致/期限切れ/試行上限超過等） |
| ログイン | `login` | 認証が完了し、新しいセッションが開始された | 発生時刻、主体ID（`sub`）、対象サービス、認証手段（`amr`）、セッションID、結果（成功/失敗） |
| ログアウト | `logout` | 利用者の明示的な操作によってセッションが終了された | 発生時刻、主体ID（`sub`）、対象サービス、セッションID、結果（成功/失敗） |
| 失効 | `session_revoke` | パスワード変更、クレデンシャル削除、セキュリティ対応等によりセッションが無効化された | 発生時刻、主体ID（`sub`）、対象サービス、セッションID、失効理由、結果（成功/失敗） |
| 上限で切った | `session_limit_exceeded` | 同一主体・サービスにおける同時ログインセッション数の上限に達したため、古いセッションが切断・失効された | 発生時刻、主体ID（`sub`）、対象サービス、失効したセッションID、結果（成功） |
| 無操作で切れた | `session_timeout` | 無操作時間の上限を超過したため、セッションが自動的に切断・終了された | 発生時刻、主体ID（`sub`）、対象サービス、セッションID、最終操作時刻、結果（成功） |
| 運営者の操作 | `admin_action` | 運営者による管理操作（強制ログアウト、特定主体のセッション全失効、記録の照会・抽出等）が行われた | 発生時刻、運営者ID、対象の主体ID（`sub`）、操作種別、対象セッションID（該当する場合）、結果（成功/失敗） |

※表中の項目において、個人情報や認証用秘密値（平文のメールアドレス、確認コード等）は含めず、識別子や区分、結果のみを残します。

---

## 入力の値を残さない決まり

個人情報の保護および漏洩リスク最小化のため、以下の入力値はログにもデータベースの記録（表）にも**決して平文で残しません**。

1. **対象となる入力値**
   - メールアドレス（ログイン時やコード発行時に入力された宛先）
   - 確認コード（発行された6桁コード、利用者が入力したコード）
   - パスキーの署名データおよび秘密鍵（公開鍵のみ別途管理）
   - セッショントークンの平文（保存時は暗号学的ハッシュ値を使用）

2. **ログ（標準出力・外部転送ログ）における原則**
   - アプリケーションログ、アクセスログ、エラーログ、例外トレースのいずれにも、入力された平文のメールアドレスやコードを出力しません。
   - 不正なログイン試行や入力エラーが発生した場合であっても、入力内容そのものはログに残さず、イベント種別（例: `code_verify`）と失敗結果（例: `failure`）のみを出力します。

3. **データベースの記録（表）における原則**
   - 監査用の表（`auth_events` 等）には、メールアドレスやコードを格納する列（`email` や `code` 等）を定義しません（docs/schema.md）。
   - コード検証のために一時的に宛先やコードを保持する表（`email_codes` 等）では、平文ではなく鍵付きハッシュ（HMAC-SHA256 等）で保持し、列名にも `_hash`（`destination_hash`, `code_hash`）を用いて平文が残らないことを明示します。
