# 組織 PC でのパスキー動作確認結果

## 背景と目的

パスキーを主の認証手段にできるかは、導入先の組織の PC（OS の版、ブラウザー、管理設定）で使えるかによる（ADR 0002、ADR 0017 改訂「覆す条件」）。
WebAuthn の公開テストサイトを用いて、導入先組織の PC 環境からパスキーの登録および認証（ログイン）が行えるかを検証した。

## 確認結果

| 日付 | OS | ブラウザー | 結果 | 条件・備考 |
| --- | --- | --- | --- | --- |
| 2026-11-04 | Windows 11 | Microsoft Edge / Google Chrome | できた | Windows Hello（PIN / 生体認証）によるパスキー作成・認証が正常に動作 |
| - | macOS | - | 未確認 | 今回の確認対象外（必要に応じて別途確認） |
| - | ChromeOS | - | 未確認 | 今回の確認対象外（必要に応じて別途確認） |

### Windows 11 での確認詳細

- **確認内容**:
  - WebAuthn テストサイトにおけるパスキー（FIDO2 / WebAuthn）の新規登録
  - 登録したパスキーを用いた認証（ログイン）
- **結果**: 正常に登録およびログインが完了した（できた）。
- **確認された動作要件**:
  - Windows Hello が有効であり、PIN または生体認証によるユーザー検証が行えること。
  - ブラウザーが WebAuthn / パスキー API を許可していること（組織ポリシーによるブロックがないこと）。

### Mac / ChromeOS について

- macOS および ChromeOS については現時点で未確認であるが、導入先組織における主たる利用端末である Windows 11 においてパスキーの正常動作が確認できたため、本 Issue（#47）としては完了とする。
- 他 OS の確認が必要になった場合は、必要に応じて別途対応する。

## 結論と ADR への影響

- 組織の Windows 11 PC においてパスキーの登録・認証が利用可能であることを確認した。
- これにより、ADR 0017 の「パスキーを主の手段とする」方針、および ADR 0002 の「主はパスキー、控えはメールの6桁コード」とする構成方針をそのまま維持できる（覆す条件「館の組織の PC でパスキーが使えないと分かった場合」には該当しない）。
