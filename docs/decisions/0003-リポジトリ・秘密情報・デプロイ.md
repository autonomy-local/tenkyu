## 背景

Tenkyu は OSS で公開し、fork した人が同じ構成を自分の Cloudflare のアカウントに立てられることを目指す。止まると全サービスのログインが止まるので、配備の順番も決める。

## 決めたこと

| 項目 | 決めたこと |
| --- | --- |
| リポジトリ | 本体とデプロイ用を分けない（案） |
| IaC | Pulumi。D1、Service Bindings、秘密の値、Access のポリシーを書く |
| デプロイ | Worker のコードは wrangler |
| Pulumi の状態 | いったん手元。共有が要るようになったら GCS か R2 に移す |
| 秘密情報 | 平文でコミットしない。正本は sops と age（案） |
| 順番 | auth の口は後方互換を守り、必ず Tenkyu を先に出す |

**未決**：環境の分け方（ステージングを持つか）、誰がいつ本番に出すか、戻し方（`wrangler rollback` と D1 の移行の戻し方）。#23 の手順書と合わせて決める。

## 理由

Pulumi のスタックと Nix の flake がリポジトリにあれば、同じ構成を一つの手順で再現できる（ADR 0017）。

## 検討した他の案

- `cloudflare.config.ts`：ADR 0017 で使わないと決めた

## 覆す条件

- 複数人や CI から Pulumi を触るようになったとき：状態の置き場所を移す（`docs/environment.md`）
