# 0006. データの出口と削除

- 状態: 提案
- 関連: ADR 0017、#39

## 背景

Tenkyu には全サービスの利用者の連絡先と認証の記録がある。退会、記録の期限、運用の引き渡しの手順がないと、利用者への説明ができない。

## 決めたこと

| 項目 | 決めたこと |
| --- | --- |
| 差し替え点 | 認証の手段は `Verifier`、鍵は KeyStore、主体の台帳は差し込み口の後ろに置く |
| 認証の記録 | 期限を決めて自動で消す（#31）。**期限の値は未決** |
| 退会 | 手順を #31 で書く。**論理削除か物理削除か、バックアップから消えるまでの期限は未決** |
| 持ち出し | **形式は未決**（JSON の全件エクスポートを提案） |
| 引き渡し | Pulumi のスタックと flake、手順書（#23、#33）で同じ構成を立て直せるようにする |

**未決**：削除のとき各サービスの記録に何が起きるか。内部の ID が残るなら、何を消したと言えるか。

## 理由

出口を最初から開けておく。差し替え点があれば、特定のサービスに閉じ込められない。

## 検討した他の案

- 記録を無期限に残す：個人情報になりうる記録を持ち続けることになるので採らない

## 覆す条件

- 法令、館との取り決め、プライバシーポリシーが違う期限を求めたとき
