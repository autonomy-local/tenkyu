## 背景

engawa の認証を切り出し、同じ考え方で Workers の上に作る。Issue #4、#5、#9 がこの決定を前提にしている。

## 決めたこと

| 項目 | 決めたこと |
| --- | --- |
| 言語とランタイム | TypeScript、Cloudflare Workers |
| Node | LTS（24）。パッケージの管理は pnpm |
| バックエンド | Hono |
| 画面 | サーバー側で HTML を返す。JavaScript が要る所だけ Solid.js。確認コードの流れは JavaScript なしで通す |
| CSS | 型の付いた CSS-in-JS。第一候補は vanilla-extract。最初の画面で確かめる |
| データベース | D1 |
| 暗号 | Web Crypto API |
| テスト | Vitest と `@cloudflare/vitest-pool-workers`。Miniflare で複数の Worker と Service Binding を立てる |
| CI の `check` | 着手の条件、テンプレートの検査、型、lint、テスト（#5） |

**未決**：#4 の終了条件は `npm run` と書かれているが、pnpm に統一するか。E2E に Playwright を使うか。

## 理由

ADR 0017 のとおり。Workers の上で動く engawa の認証から移植でき、Miniflare で手元と CI に同じ構成を立てられる。

## 検討した他の案

- CSS に Panda CSS、StyleX：生成物の多さ、Solid での使い方の少なさで第一候補にしなかった（ADR 0017）
- 開発にコンテナを使う：Nix に統一したので採らない

## 覆す条件

- 最初の画面で vanilla-extract が合わないと分かったとき
- Workers で動かない依存が必要になったとき
