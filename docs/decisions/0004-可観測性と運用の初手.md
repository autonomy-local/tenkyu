## 背景

Tenkyu のログは個人情報を含みやすく、止まると全サービスに響く。運用する人数が少ないので、最初は小さく始める。

## 決めたこと

| 項目 | 決めたこと |
| --- | --- |
| 認証の記録 | `auth_events` に残す。いつ、どの手段で、結果はどうだったか |
| ログの決まり | 入力の値（メールアドレス、コード）を残さない。識別子だけを残す |
| 一時的な停止 | 各サービスは検証の結果を短い時間だけ覚え、ログイン済みの操作を止めない（ADR 0017） |
| SLO と当番 | 先送りする。#33 の手順書で扱う |

**未決**：ログの送り先と保存の期間、量の上限、障害に気づく方法と通知先、検証の結果を覚える時間。

## 理由

個人情報をログに入れないことは、後から直すのが難しいので先に決める。送り先などは小さく始めて後で足せる。

## 検討した他の案

- 最初から外部の監視サービスを入れる：費用と個人情報の送り先が増えるので、今は決めない

## 覆す条件

- 本稼働の後に障害の気づきが遅れたとき
- 利用者やサービスの数が増え、当番が要るようになったとき
