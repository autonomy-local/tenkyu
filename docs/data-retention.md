# データの保存の期限と置き場所

Tenkyu が何を、どれだけ、どこに持つかを書きます。記録を必要以上に持ち続けないためです（ADR 0006）。
表の定義は [schema.md](schema.md)、データの重さは ADR 0001 にあります。

> **未決**：「期限」と「退会のとき」の **〔案〕** は、エージェントの提案です。値と、論理削除か物理削除かは人が決めて、この文書に書き込みます（ADR 0006 の未決）。決まったら〔案〕を外します。

## 置き場所

- すべて Tenkyu の D1 に置きます。D1 の置き場所は **アジア太平洋**（location hint `apac`）までの指定です。国内に置くことは先送りしています（ADR 0017「設計の仕分け」）
- プライバシーポリシーには置き場所の地域を書きます（ADR 0017「実装上の注意」2）
- 移行の間は、メールアドレスが Firebase（Google）の側にも残ります。#32 で外すまでの間だけです（ADR 0001、ADR 0017「実装上の注意」2、[migration.md](migration.md)）
- D1 の Time Travel（その時点への戻し）の保持の期間の間は、消した行が戻せる状態で残ります。期間は Cloudflare のプランで決まり、Free が7日、Paid が30日です。本番のプランは **〔案〕Paid（30日）**

## データごとの期限

| データ | 中身 | 期限 | 置き場所 |
| --- | --- | --- | --- |
| `identities` | 主体の ID（`sub`）と、認証の手段（プロバイダと、その中の識別子）の対応 | 主体が有効な間。無効にした手段（`disabled_at`）は、無効にしてから **〔案〕30日** で消す | D1（アジア太平洋） |
| `sessions` | セッショントークンのハッシュ、主体の ID、サービス、認証の手段、時刻 | 切れたか失効した（`expires_at`・`revoked_at`）あと **〔案〕30日** で消す | D1（アジア太平洋） |
| `auth_events` | 認証の記録。出来事の種類、主体の ID（分かるときだけ）、サービス、手段、結果、時刻。入力の値は持たない | 記録してから **〔案〕1年** で消す | D1（アジア太平洋） |
| `email_codes` | 宛先とコードの鍵付きハッシュ、有効期限、試行の回数、使った時刻 | 有効期限を過ぎたか使ったあと **〔案〕1日** で消す | D1（アジア太平洋） |
| パスキー | 公開鍵とクレデンシャルの ID。秘密鍵は持たない（利用者の端末にある） | 主体が有効な間。利用者か運営者が外したら、すぐに消す | D1（アジア太平洋）。表は未定義（[schema.md](schema.md) に足す） |

- 期限を過ぎた行の削除は、Cron Trigger で自動で行います（次-8b）。期限の値は設定で持ちます

## 退会のとき

主体の削除の口（次-8c）で、主体ごとに次のように扱います。

| データ | 退会のとき |
| --- | --- |
| `identities` | **〔案〕物理削除**。メールアドレスに当たる識別子と外部の ID を残さない |
| `sessions` | **〔案〕物理削除**。先に失効させてから消す |
| `auth_events` | **〔案〕主体の ID を外して残す**（`sub` を `NULL` にする）。残りは上の期限で消える |
| `email_codes` | **〔案〕物理削除**。主体の ID を持たないので、宛先のハッシュで当たる行を消す。消し漏れても上の期限で消える |
| パスキー | **〔案〕物理削除** |

- 退会のときの期限は、次の3つに分けて伝えます

| 期限 | 中身 |
| --- | --- |
| 物理削除 | **〔案〕退会の受付から7日以内**に、上の表のとおり D1 から消す |
| Time Travel から消えるまで | 物理削除から **〔案〕30日**（Paid の保持の期間）。この間は戻せる状態で残る |
| 利用者への通知 | **〔案〕退会の受付のときに**、上の2つを足した、D1 の Time Travel から消える予定日（受付から37日以内）を伝える。バックアップと各サービスの側の消去の期限は未決（ADR 0006） |

- 各サービスの側に残る主体の ID の扱いは未決です（ADR 0006 の未決）
