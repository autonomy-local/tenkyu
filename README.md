# Tenkyu（天球）

地域の組織が使うサービスのための、小さなアカウント基盤です。
「この人は誰か」を確かめる部分だけを受け持ち、Cloudflare Workers の上で動きます。

## 名前の由来

天球（てんきゅう）は、星の位置を測るために、地球を包むように思い描く大きな球です。
航海や測量では、星の位置を手がかりに、自分がどこにいるかを確かめてきました。
Tenkyu は、利用者が誰であるかを確かめる、基準の点になることを目指して、この名前を付けました。

## 何をするか

- **本人の確かめ**：パスキー、メールの確認コード（6桁）で、利用者が本人であることを確かめます
- **セッション**：ログインの状態をサーバー側で持ち、各サービスからの問い合わせに答えます
- **認証の記録**：いつ、どの手段でログインしたかを残します

## 何をしないか

- **パスワードを持ちません**
- **所属や役割を持ちません**：誰がどの組織に属し、何ができるかは、各サービスか、台帳を受け持つ別の基盤が持ちます。Tenkyu が守るのは「同時にいくつまでログインできるか」「何分操作がなければ切れるか」といった、渡された数字だけです
- **利用者の業務のデータを持ちません**

## 設計の考え方

### 主体と認証の手段を分ける

利用者には、Tenkyu が発行する内部の ID を一つだけ割り当てます。
パスキー、メールの確認コード、外部の認証サービスなどの「確かめ方」は、その ID にひもづく別の行として持ちます。
確かめ方を足したり替えたりしても、内部の ID は変わらず、各サービスの記録と権限は切れません。

| 表 | 中身 |
| --- | --- |
| `identities` | 確かめ方（手段の種類と、手段ごとの識別子）。内部の ID にひもづく |
| `sessions` | ログインの状態 |
| `auth_events` | 認証の記録 |

### 個人の情報は一か所に

メールアドレスとパスキーの公開鍵は、Tenkyu の中だけに置きます。
Tenkyu を使う各サービスには内部の ID だけを渡し、メールアドレスは渡しません。

ただし、内部の ID とそれにひもづく利用の記録も、照合できれば個人の情報になりえます。
Tenkyu は「個人の情報を持たない」とは言わず、「氏名や連絡先は一か所に置き、ほかは識別子と最小限の記録にとどめる」ことを目指します。

### 外の相手には、相手ごとに違う ID を

将来、OpenID Connect で外部のサービスとつなぐときは、相手ごとに違う ID（ペアワイズの識別子）を渡します。
異なるサービスの間で、同じ人を名寄せできないようにするためです。

### 誰でも使えるようにする

- **らくらくスマートフォンや、LINE の中のブラウザでも使えること**を前提にしています。メールの確認コードは、リンクを開くと別のブラウザに移ってしまう環境や、メールの先読みでリンクが無効になる問題を避けるためのものです
- 端末をなくした時のために、パスキーだけに頼らず、メールの確認コードを逃げ道として残します

## つなぎ方

同じ Cloudflare のアカウントの中のサービスからは、**Service Bindings** で呼び出します。
各サービスは、ログインの状態を Tenkyu に問い合わせて確かめます。

```
利用者 ──▶ サービス（例：施設の予約、アーカイブ）
                │  Service Binding
                ▼
             Tenkyu（内部専用の Worker）──▶ D1
```

## これからの予定

| 段階 | 内容 |
| --- | --- |
| 今 | メールの確認コード、外部の認証サービス（移行の間）、セッション、Service Bindings |
| 次 | パスキー |
| その先 | OpenID Connect のプロバイダ（外部のサービスとつなぐとき）、検証可能な資格情報（Verifiable Credentials）の発行 |

検証可能な資格情報について、次のことを原則にしています。

- 組織の名義の証明を、開発者が単独で発行することはしません
- 証明を持ち歩く財布（ウォレット）は作らず、標準の規格（OpenID for Verifiable Presentations）で、利用者が使う財布に渡します
- 証明に書くのは事実（いつ、どの役割を担ったか）までとし、評価は書きません

発行の方式は、国の検討（発行の要件、財布の要件）の行方に合わせて決めます。

## 開発の環境

手元でも CI でも同じ版の道具で開発できるように、Nix（flake）で開発環境を管理しています。

### 前提条件

- [Nix](https://nixos.org/) がインストールされ、Flakes が有効になっていること

### 始め方

リポジトリの直下で次のコマンドを実行すると、開発に必要な道具（Node.js、pnpm、wrangler、Pulumi など）が揃ったシェルに入ります。

```bash
nix develop
```

direnv を使っている場合は、初回に `direnv allow` を実行すると、リポジトリに入るだけで自動的に環境が読み込まれます。

シェル内で以下のコマンドが実行できることを確認できます。

```bash
node --version
pnpm --version
wrangler --version
pulumi version
```
